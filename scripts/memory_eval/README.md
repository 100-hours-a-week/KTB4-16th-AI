# 기능5 기억 검색 정확도 측정

질문 30개로 "결과 위 3개 안에 정답 기록이 있는 비율(Hit@3)"을 잰다. 외부 호출·비용이 없고,
유사도 기준값·가중치를 바꿔 가며 같은 질문으로 반복 측정할 수 있다.

## 방식
- **실제 그대로**: 질문 해석(QuestionParser), 조건 점수, 점수 합치기, 안내 문장 (`MemorySearchService`)
- **메모리 가짜**: pgvector 검색(코사인을 파이썬으로 계산), 백엔드 MySQL 상세 조회
- **임베딩**: 실제 KURE-v1 ONNX (벡터는 `data/memory_eval/vectors_kure.json`에 저장해 두고 다시 쓴다)
- 그래서 **실제 SQL(pgvector·MySQL 쿼리)은 측정에 포함되지 않는다.** 그 부분은 개발서버에서 따로 확인한다.

## 시험 데이터
- 가상 사용자 4명 × 자물쇠 25건. 코멘트는 임베딩 평가의 100개(`eval/text_embedding/corpus.jsonl`)를 재사용
- 장소·날씨·기온·기분·날짜·곡 무드는 무작위. 경계 근처 값(기온 5/6·15/16·25/26도, 기분 ±20 근처,
  명소 반경 근처)은 일부러 안 만들어서 "애매한 정답"이 없다
- 질문마다 정답 기준(`filter`)이 있고, 정답은 그 기준을 만족하는 기록으로 **자동 계산**한다
  (사람이 하나씩 라벨링하지 않는다). 코멘트 의미 질문만 임베딩 평가에서 사람이 정한 정답을 재사용한다
- 정답이 너무 적은 질문은 조건에 맞는 기록을 몇 개 "심는다" (`dataset.json`의 `planted`)

## 파일
| 파일 | 역할 |
|---|---|
| `questions.yaml` | 질문 30개와 정답 기준. **질문 문장은 자유롭게 고쳐도 된다** (정답 기준을 그대로 두면 정답도 그대로) |
| `build_dataset.py` | 시험 데이터 생성 → `data/memory_eval/dataset.json`, `questions_draft.md` |
| `run_eval.py` | 측정 실행 → `data/memory_eval/results_<이름>.md/.json` |

## 실행
```bash
# 1) 시험 데이터 (같은 --seed면 같은 결과)
PYTHONPATH=. .venv/bin/python scripts/memory_eval/build_dataset.py

# 2) 측정. onnxruntime·tokenizers가 있는 파이썬이 필요하다 (프로젝트 .venv에는 없다)
EXTRA_SITE_PACKAGES=<.venv의 site-packages> PYTHONPATH=. \
    <onnxruntime 있는 python> scripts/memory_eval/run_eval.py --model-dir <KURE ONNX 폴더>

# 설정 비교 (이름을 다르게 주면 결과가 따로 저장된다)
... run_eval.py --model-dir <폴더> --min-similarity 0.55 --name minsim_0.55
... run_eval.py --model-dir <폴더> --condition-weight 0.3 --name condw_0.3
```

## 지표
- **Hit@3**: 질문마다 위 3개 안에 정답이 하나라도 있으면 성공 (정답 있는 질문만)
- **무작위 기준**: 25건 중 정답이 g건일 때 아무 3건이나 골라도 맞을 확률. 점수가 이보다 얼마나 나은지를 봐야 한다
- **정답 없는 질문**: 결과가 비어 있으면 성공. Hit@3과 따로 센다
- Precision@3, MRR은 보조 지표

## 결과를 읽을 때 주의
- **질문이 서비스가 아는 말로 쓰여 있으면 쉽다.** 초안 질문은 규칙 파일에 있는 표현("비 오는 날", "추웠던")을
  썼기 때문에 조건 질문은 거의 만점이 나온다. 실제 사용자가 쓰는 표현으로 바꿔야 진짜 성능이 보인다
- 조건 질문은 "모든 조건을 만족하는 기록"이 먼저 나와서, 정답 안의 순서는 Hit@3에 영향이 없다.
  그래서 조건 가중치를 바꿔도 점수가 안 변한다 (이 지표로는 가중치를 정할 수 없다)
- 질문 30개는 적어서 1개가 3.3%p다. 설정을 조정한 질문으로 최종 평가를 하면 점수가 낙관적이 되므로
  조정용과 최종 평가용을 나누는 게 좋다
- 시험 데이터는 임베딩 평가의 합성 코멘트라 실제 일기와 다르다

## 첫 측정 (2026-10-16, KURE-v1, 최소 유사도 0.65)
- Hit@3 약 96% (정답 있는 27개 중 26개), 무작위 기준 약 45%. 코멘트 의미 질문 6개 중 1개 실패
  ("퇴근길에 들은 노래" — KURE가 출근/퇴근을 구분하지 못하는 것이 임베딩 평가에서도 확인된 약점)
- 최소 유사도를 바꿔 본 결과: 0.65~0.70에서 정답 없는 질문이 모두 빈 결과이고 코멘트 의미 질문도 유지됨.
  0.55 이하에서는 정답 없는 질문에 엉뚱한 결과가 나오고(0.40이면 25건 중 23건), 0.75부터는 코멘트 의미
  질문이 거의 안 나옴(1/6). 이 값들은 합성 시험셋 기준의 임시 판단이다
