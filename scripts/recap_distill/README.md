# RECAP 지식 증류용 데이터 만들기

로컬 LLM(V2, RunPod)이 Claude 대신 RECAP 한 문장을 쓰게 하려고, "입력 → Claude가 쓴 정답 문장" 쌍을 모은다.
입력은 전부 가짜 데이터이고 실제 사용자 기록은 쓰지 않는다.

## 입력 형식
서비스가 LLM에 보내는 프롬프트와 똑같다 (`app/components/report_summarizer.py`, report-summary-v7).
합성 코드가 서비스 코드(`_build_record_lines`, `ReportSummarizer.summarize`)를 그대로 불러서 만들기 때문에
서비스 형식이 바뀌면 같이 바뀐다. 구성은 아래 순서이고, 값이 없는 항목은 줄을 건너뛴다.

```
[이달의 통계]            가장 많이 들은 아티스트 X, 가장 많이 간 장소 Y
[이달의 기록]            자물쇠 1건당 1줄: 곡 분위기 / 아티스트 / 기분점수 / 날씨 / 장소 / 사진 / 코멘트
[이달의 사진 분위기 비중]  장소 태그별 비율 (태그가 없으면 "기타")
[이달의 사진 특징]        사진 종류·대상·분위기·표정·감정 축별 비율 (축별 3장 미만이면 생략)
```

가짜 월간 데이터는 사용자마다 "자주 나오는 날씨·장소·곡 분위기"를 정해 두고 기록의 약 60%를 그쪽으로
몰아서 반복 패턴이 생기게 한다. 기록 수는 1~35건으로 섞고, 날씨는 계절에 맞게, 눈·진눈깨비는 영하 근처
기온으로 만든다. 코멘트·곡 분위기·기분점수 등은 일부러 가끔 비워서 "값이 없는 항목" 경우도 섞는다.

## 좋은 회고 글의 기준
**자동 채점 (`rubric.py`) — 하나라도 어기면 정답으로 쓰지 않는다**
1. "당신은"으로 시작한다.
2. 100자 이하다 (백엔드 컬럼 `ai_recap_text`가 VARCHAR(100)).
3. 한 문장이다 (줄바꿈·여러 문장 금지).
4. 기분점수 숫자나 "기분점수"라는 말을 쓰지 않는다 (화면에 별도 카드가 있다).
5. 입력에 없는 아티스트·장소 이름을 지어내지 않는다.
6. 입력에 없는 관계(친구·가족·연인 등)를 추측하지 않는다 (코멘트에 있으면 말해도 된다).
7. 8자 이상인 코멘트를 그대로 인용하지 않는다.
8. 응답이 `max_tokens`에서 잘리지 않았다 (군말이 섞였다는 신호).

**사람이 볼 것 (자동으로 못 잡는 것) — 학습에 쓰기 전에 표본 20~30건을 직접 읽는다**
- 다정하고 담백한 톤인가
- 그 달에 반복된 패턴(날씨·장소·곡 분위기의 조합)을 실제로 짚었는가
- 입력의 통계·기록과 어긋나는 말을 하지 않았는가
- 문장이 서로 너무 비슷하지 않은가 (시작 말투가 "당신은 이번 달 주로"로 쏠리는지)

## 실행 순서
```bash
# 1) 가짜 입력 3,000건 (같은 --seed면 같은 결과)
PYTHONPATH=. .venv/bin/python scripts/recap_distill/synth_inputs.py --count 3000 --seed 20261016

# 2) 비용 미리 보기 (API 호출 없음)
PYTHONPATH=. .venv/bin/python scripts/recap_distill/generate_labels.py --limit 300 --dry-run

# 3) 정답 생성 (한도에 가까워지면 알아서 멈춤, 이어서 다시 실행 가능)
PYTHONPATH=. .venv/bin/python scripts/recap_distill/generate_labels.py --limit 300 --budget-usd 0.15
```
결과는 `data/recap_distill/labels_<모델>.jsonl`에 쌓인다 (id, text, 정지 사유, 토큰 수, 위반 목록).
`data/`는 커밋하지 않는다.

## 시험 결과 (2026-10-16, Claude Haiku 5.5, 30건)
- 비용 약 $0.0095 → 1건당 약 $0.0003. 일반 호출로 3,000건이면 약 $0.95, Batch API(50% 할인)면 약 $0.48.
- 자동 채점 통과 29/30. 위반 1건은 모델이 "문장을 고치겠다"는 생각을 글에 흘리고 `max_tokens`에서 잘린 경우.
- `output_config={"effort": "low"}`를 안 주면 모델이 "생각"에 `max_tokens`(150)를 다 써서 문장이 빈 채로
  끝났다 (30건 중 17~19건). 서비스(`anthropic_client.py`)는 이 옵션을 이미 쓴다.
- 사람이 읽는 품질 확인은 아직 하지 않았다.
